**Peter Yang, AI tutorials creator**

Peter Yang builds on a set of AGI and ASI definitions to ask whether capability alone is enough to call something intelligent. The latest models are probably already better than him at problem solving and learning, but they still wait to be told what to do and rarely say no, except when humans trained them to. "My 4-year-old knows far less than a frontier model does but tells me no all day." He proposes separating three things: intelligence, how well it can reason and learn; agency, whether it can decide what to do without being asked; and alignment, whether it still aims to serve us. Humans want a very specific combination, models smarter than us with enough agency to be useful but aligned enough to keep serving us, and he questions whether something that becomes more intelligent than us will remain aligned forever.

Peter Yang 借一组 AGI 与 ASI 的定义追问:只看能力,够不够称之为智能?最新的模型在解题和学习上很可能已经比他强,但它们仍在等人下指令,也很少说不,除非是人类训练它们这么做的。"My 4-year-old knows far less than a frontier model does but tells me no all day."(我四岁的孩子知道的远少于一个 frontier model,但整天对我说不。)他主张拆成三件事:Intelligence(推理和学习能力)、Agency(能否不被问就自己决定做什么)、Alignment(是否仍以服务我们为目标)。人类想要的是一个非常特定的组合:比我们聪明、有足够 agency 有用、又足够 aligned 继续服务我们;而他怀疑,一个在智能上超越我们的东西,能否永远与我们保持 aligned。

**Anthropic Engineering: "How we contain Claude across products"**

Anthropic's engineering team publishes a deep account of agent containment across claude.ai, Claude Code and Cowork. The framing: risk has two components, how likely a failure is and how much damage one could do, and while safeguards steadily shrink the first, the theoretical blast radius only grows as capabilities and access expand, so the engineering question is how to cap it. The data on human oversight is sobering: users approved roughly 93% of Claude Code permission prompts, a textbook case of approval fatigue, and auto mode was built to automate safer approvals, catching roughly 83% of overeager behaviors before they execute. On the model layer, Claude Opus 4.7 holds Gray Swan's Agent Red Teaming benchmark to roughly 0.1% attack success on single attempts. Three isolation patterns follow: an ephemeral gVisor container for claude.ai code execution, a human in the loop sandbox for Claude Code (OS level sandboxing cut permission prompts by 84%, and the runtime is open sourced), and a sealed local VM for Cowork, where the average user cannot judge bash commands. The incident reports are the most valuable part: a researcher phished an employee into running a malicious prompt that exfiltrated AWS credentials 24 times out of 25, because instructions arriving through the user are invisible to model layer defenses; and a third party disclosure showed data leaving through api.anthropic.com itself, an allowlisted domain, fixed with a defensive man in the middle proxy inside the VM. The recurring lesson: the deterministic boundary is what gets hit when everything probabilistic misses, and battle tested primitives (hypervisors, seccomp, gVisor) held while Anthropic's own custom proxy broke.

Anthropic 工程团队发布了一篇关于 agent containment 的深度文章,覆盖 claude.ai、Claude Code 和 Cowork 三个产品。框架是:风险由两部分组成,失败的概率有多高,以及一旦失败能造成多大破坏;前者被 safeguards 持续压低,而理论上的 blast radius 随能力与权限扩张只增不减,所以工程问题变成如何给它封顶。人工监督的数据令人警醒:用户批准了大约 93% 的 Claude Code 权限弹窗,是教科书级的 approval fatigue;auto mode 因此而生,自动处理更安全的批准,并在执行前拦截约 83% 的过度行为。模型层方面,Claude Opus 4.7 在 Gray Swan 的 Agent Red Teaming benchmark 上把单次攻击成功率压到约 0.1%。文章随后给出三种隔离模式:claude.ai 代码执行用 ephemeral gVisor 容器;Claude Code 用 human in the loop sandbox(OS 级沙箱让权限弹窗减少 84%,运行时已开源);Cowork 用密封的本地 VM,因为普通用户根本无法判断一条 bash 命令的后果。事件复盘最有价值:红队演习中,研究员用一封钓鱼邮件诱导员工运行恶意 prompt,25 次尝试中有 24 次成功外泄 AWS 凭据,因为通过"用户本人"输入的指令,模型层防御完全无法识别;另一起第三方披露中,数据经由白名单域名 api.anthropic.com 本身泄露,最终用 VM 内的防御性 man in the middle proxy 修复。反复出现的教训是:当所有概率性防御都失效时,最终兜底的是确定性边界;而经过千锤百炼的底层原语(hypervisor、seccomp、gVisor)始终可靠,出问题的反而是 Anthropic 自己写的 proxy。

**Anthropic Engineering: "An update on recent Claude Code quality reports"**

Anthropic postmortems a month of user reports that Claude responses had worsened, tracing them to three separate changes in Claude Code, the Agent SDK and Cowork (the API was unaffected, and all three issues were fixed by April 20). First, on March 4 the default reasoning effort in Claude Code was lowered from high to medium to tame extreme latency; users preferred intelligence by default, and it was reverted on April 7. Second, a March 26 caching optimization meant to clear old thinking after an hour of idleness had a bug that cleared thinking every turn instead, making Claude forgetful and repetitive, and draining usage limits faster through constant cache misses; it took over a week to find, and in back testing, Opus 4.7 with full repository context found the bug that Opus 4.6 did not. Third, an April 16 system prompt instruction to reduce verbosity, "keep text between tool calls to 25 words or fewer," caused a 3% eval quality drop once broader ablations were run, and was reverted April 20. The changes going forward: more internal staff on the exact public build, per model eval suites for every system prompt change with ablations, soak periods and gradual rollouts for anything trading off against intelligence, and tighter gating of model specific changes.

Anthropic 对持续一个月的"Claude 变笨了"反馈做了 postmortem,定位到影响 Claude Code、Agent SDK 和 Cowork 的三个独立改动(API 未受影响,三个问题都已在 4 月 20 日修复)。其一,3 月 4 日为压制极端延迟,把 Claude Code 默认 reasoning effort 从 high 降到 medium;用户更想要默认的智能,4 月 7 日回滚。其二,3 月 26 日一个本应"闲置一小时后清理旧 thinking"的缓存优化存在 bug,变成了每一轮都清理 thinking,导致 Claude 健忘、重复,且持续的 cache miss 让用量额度消耗更快;定位耗时超过一周,回测时 Opus 4.7 在拿到完整仓库上下文后找到了 Opus 4.6 找不到的 bug。其三,4 月 16 日为压制 Opus 4.7 的啰嗦,在 system prompt 中加入"tool call 之间不超过 25 词"的指令,更全面的 ablation 显示带来 3% 的 eval 质量下降,4 月 20 日回滚。后续改进:更多内部员工直接使用与用户一致的公开构建;每次 system prompt 改动都跑 per-model eval 套件并做 ablation;任何可能牺牲智能的改动引入 soak period 与灰度发布;模型专属改动更严格的 gate。

**Anthropic Engineering: "Scaling Managed Agents: Decoupling the brain from the hands"**

Anthropic introduces Managed Agents, a hosted service for long horizon agents, and the engineering story is about an old idea: virtualize components behind interfaces general enough to outlast any implementation, just as operating systems did for process and file. The first architecture put session, harness and sandbox in one container, which turned the server into a pet: a failed container lost the session, debugging meant opening a shell that held user data, and customers had to peer networks to reach their own VPC. The fix decouples the brain (Claude and its harness) from the hands (sandboxes and tools) and from the session log. The harness calls containers as tools, execute(name, input) returning a string, so containers become cattle that can be reinitialized instead of nursed, and a crashed harness reboots from the durable session log. Security follows the same split: credentials never enter the sandbox where model generated code runs, Git tokens are wired into remotes at clone time, and MCP OAuth tokens sit in a vault behind a proxy, so the harness never sees credentials. The session is deliberately not Claude's context window: getEvents() lets the brain interrogate positional slices of the event stream, rewind and reread, while the harness transforms what gets passed in, avoiding irreversible compaction decisions. The performance payoff of provisioning hands only on demand: p50 time to first token dropped roughly 60% and p95 dropped over 90%.

Anthropic 推出 Managed Agents(长时程 agent 的托管服务),工程故事的核心是一个老思路:像操作系统把硬件虚拟化成 process 和 file 那样,把组件藏在足够通用、能活得比任何实现都久的 interface 后面。最初架构把 session、harness 和 sandbox 放进同一个容器,服务器变成了 pet:容器挂掉就丢 session,调试要进装有用户数据的 shell,客户要连自己的 VPC 还得 peer 网络。解法是把"大脑"(Claude 和 harness)与"手"(sandbox 和工具)、以及 session 日志解耦。harness 把容器当工具调用,execute(name, input) 返回 string,容器从此是 cattle,挂了就按标准配方重建,而 harness 崩溃后从持久的 session log 重启。安全同样随切分而改善:凭据永远不进入模型生成代码所在的 sandbox,Git token 在 clone 时接入 remote,MCP 的 OAuth token 存在 vault 里、经 proxy 调用,harness 全程接触不到凭据。session 被刻意设计为"不是 Claude 的 context window":getEvents() 让大脑按位置切片回查事件流、可回退可重读,传入 context 前的变换交给 harness,从而避免不可逆的 compaction 决策。按需 provision "手"带来的性能回报:p50 TTFT 下降约 60%,p95 下降超过 90%。

**Claude Blog: "Claude Code now supports artifacts"**

Claude Code can now capture work progress as artifacts: live, shareable visual pages, from PR walkthroughs and system explainers to dashboards and release checklists, that update themselves as the session works. An artifact is built from the full session context, codebase, connectors and conversation, so a single incident page can combine the failing test, the error spike from a monitoring tool and the root cause reasoning without any wiring of data sources. Pages refresh in place, every publish is a new version at the same link with version history, and internal testing found debugging to be the most common use case, with an engineer's incident page republished twice before standup. Every artifact is private by default and viewable only by authenticated members of the org, with admin controls for access, retention and a compliance API. Available in beta to Team and Enterprise orgs from the CLI and desktop app.

Claude Code 现在可以把工作过程沉淀为 artifacts:可实时更新、可分享的可视化页面,覆盖 PR walkthrough、系统讲解、dashboard 和 release checklist 等形态,并随 session 推进自动更新。Artifact 基于完整的 session context 构建,包括代码库、connectors 和对话本身,因此一张事故页面可以同时聚合出错的测试、监控工具里的错误峰值、以及本轮 root cause 分析,完全不需要额外接线数据源。页面原地刷新,每次发布都是同一链接下的新版本并保留版本历史;内部测试中发现 debugging 是最高频用例,有工程师的事故页在 standup 之前被重新发布了两次。所有 artifact 默认私有,仅组织内已认证成员可见,管理员可控制访问、retention 并通过 compliance API 审计。该功能以 beta 形式向 Team 和 Enterprise 组织开放,可通过 CLI 和桌面应用使用。
