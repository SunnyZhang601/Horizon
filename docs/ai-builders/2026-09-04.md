**Claude Blog: "Claude in Chrome is generally available"**

Claude in Chrome is now generally available on every paid Claude plan, and Claude can now take actions autonomously in the browser instead of needing approval for each one, with a safety classifier validating every action against what you originally asked for. The post is also a detailed account of the prompt injection defense work that made GA possible: a growing attack library fed by internal automated attackers, external red teamers and real world monitoring; probes that screen tool results for malicious instructions and warn Claude to treat suspicious content carefully; and automatic approval classifiers adapted from Claude Code's auto mode. The evaluation numbers are striking: on stronger attacks sourced by professional red teamers, attacks that reached the model succeeded against Opus 4.5 17.6% of the time and Opus 5 3.8%; from Opus 4.8 onwards, with probes and the safety classifier, no attacks succeeded against Sonnet 5, Opus 5 or Mythos 5, and only 0.3% succeeded against Fable 5, all in low severity scenarios. Enterprise admins can manage the extension in Organization Settings and limit it to approved domains.

Claude in Chrome 现已在所有付费 Claude 计划上正式可用(GA),Claude 可以在浏览器中自主执行操作,而不必逐项等待批准,同时由一个 safety classifier 校验每个动作是否与你最初的要求一致。这篇文章同时详细记录了支撑 GA 的 prompt injection 防御工作:一个不断扩充的攻击库,由内部自动化攻击者、外部红队和真实监控共同供稿;probes 会在工具结果中扫描恶意指令,一旦发现疑似攻击就提醒 Claude 提高警惕;以及沿用 Claude Code auto mode 思路的自动批准 classifier。评测数字非常亮眼:在使用专业红队提供更强攻击的评测中,到达模型的攻击对 Opus 4.5 成功率为 17.6%,对 Opus 5 为 3.8%;而从 Opus 4.8 起,配合 probes 和 safety classifier,对 Sonnet 5、Opus 5 和 Mythos 5 的攻击成功率为 0,对 Fable 5 也只有 0.3%,且全部属于低危场景。Enterprise 管理员可以在 Organization Settings 中管理该扩展,并将其限制在批准的域名内。

**Claude Blog: "Claude gets its own browser in Cowork"**

Claude now has a browser built into Claude Cowork in the desktop app: when a task needs a website, a browser opens in the side panel and Claude navigates pages, reads them, clicks and types, so you can hand off the web part of a task and keep working. Key design choice: it is Claude's browser, not yours. It is separate from your own, Claude never sees your tabs, bookmarks or passwords, and you bring logins over site by site from Chrome, Edge or Firefox on macOS and Firefox on Windows and Linux, with banking, email and single sign on sites excluded unless you opt in. The post draws a clear line between the two web modes: the built in browser is for handing off web tasks while you work elsewhere, while Claude in Chrome is for the page you already have open with the accounts you are already signed into. It carries the same prompt injection safeguards as Claude in Chrome, and rolls out over the coming week to Pro, Max and Team plans on macOS, Windows and Linux (in beta), with Enterprise admins able to enable it in Organization settings.

Claude 桌面应用的 Cowork 中现在内置了一个浏览器:当任务需要访问网站时,浏览器会在侧边栏打开,Claude 自行导航网页、阅读、点击和输入,你可以把任务的网页部分整个交出去,自己继续做别的事。关键设计在于:这是 Claude 的浏览器,不是你的。它与你自己的浏览器相互隔离,Claude 看不到你的标签页、书签或密码;你需要逐站点导入登录状态(macOS 上支持 Chrome、Edge、Firefox,Windows 和 Linux 上支持 Firefox),银行、邮箱和 SSO 站点默认排除,除非你主动加入。文章还清晰划分了两种上网模式:内置浏览器适合把网页任务整体交给 Claude,而 Claude in Chrome 适合处理你已经打开、已经登录的那个页面。它沿用了与 Claude in Chrome 相同的 prompt injection 防护,并将在未来一周内向 Pro、Max 和 Team 计划推送(macOS、Windows 和 Linux,beta),Enterprise 管理员可在 Organization settings 中开启。
